01 / WHAT IT IS

你打开的到底是什么：GDevelop 与在线编辑器

GDevelop 是一个开源、以 2D 为主的无代码游戏引擎。在线编辑器则是把同一个编辑器搬进浏览器：不用安装，打开网页就能做。理解这一点，能帮你判断什么时候该用它、什么时候该换桌面版。

GGDevelop 本身

一个免费、开源（MIT 许可证）的游戏引擎，主打“事件驱动”的可视化逻辑。它把游戏拆成场景（Scene）、对象（Object）、实例（Instance）、行为（Behavior）和事件（Event）。

它最擅长的不是写实 3D，而是 2D 平台、俯视角、解谜、弹幕、点击、放置、视觉小说式的小游戏和原型。

◎在线编辑器

地址固定为 editor.gdevelop.io。它把编辑器跑在浏览器里，项目可以存到 GDevelop 云，也可以选择“现在不保存此项目”做临时实验。

它和桌面版共享同一套项目格式与核心功能。区别主要在文件管理、离线能力、性能和打包方式，不在“能不能做游戏”。

03 / ACCOUNT & CLOUD

注册、登录与云项目：先把“东西不会丢”这件事搞定

做游戏最打击人的不是 bug，而是做了两小时的东西刷新没了。先花五分钟把账号和保存方式弄对，后面会轻松很多。

打开编辑器，点右上角“注册”

在线编辑器首页右上角有 Ask AI、获取应用程序、登录、注册 和语言切换。点“注册”，按页面提示创建账号。

常见方式包括邮箱注册，以及 Google / GitHub / Apple 等第三方登录；具体以你打开时登录页显示的选项为准。

完成邮箱验证（如果要求）

用常用邮箱注册，收到验证邮件后点链接。没收到就看垃圾邮件；仍然没有就换一个邮箱或稍后再试。不要在共享电脑上保存密码。

回到“创建”，新建项目并选“GDevelop 云”

登录后创建项目，存储位置选 GDevelop 云。如果未登录就选云，系统会提示你先创建账号——这是正常的，不是报错。

云项目怎么保存：看到“已保存”再关页面

自动保存，但不是“瞬移”

云项目会在你编辑时自动保存。网络慢的时候，保存会滞后。做完一段关键改动后，停两秒，确认界面上的保存状态再继续。

如果你要关电脑、换设备，先回到项目列表，确认项目卡片是最新状态，再关标签页。

这些操作会让云项目“没保存”

  • 断网后继续大改，然后直接关页面。
  • 同一项目在两台设备同时打开、同时改。
  • 用无痕/隐私窗口，关掉后本地缓存清空。
  • 把“现在不保存此项目”当成正式项目。
免费 3 个云项目怎么管：一个项目 = 一个游戏。游戏里的不同关卡用“场景（Scene）”区分，不要为每一关新建一个项目。旧实验项目做完就导出/截图留档，然后删掉，腾出名额。
账号与公开发布的安全习惯

用昵称，不用真名

gd.games 上的作者名、游戏页可能公开。不要用真实姓名、学校、住址、常用社交账号当用户名。

游戏里不放个人信息

包括真实照片、位置、学校、电话号码、聊天账号。发布前把测试用的占位文字清掉。

付费与发布前先问清楚

订阅会自动续费；公开发布意味着任何人可见。未成年人请在监护人知情的情况下操作付费和发布。

GDevelop 的服务条款、隐私政策和年龄要求以其官网为准。这份指南不替代监护人的判断，也不鼓励瞒着家人注册或付费。

先搞懂“对象”和“实例”

对象 = 饼干模具

对象是蓝图：它的图片、动画、碰撞掩码、行为都定义在这里。你在对象面板里改的是“这一类东西”。

例：Coin 这个对象长什么样、有没有动画。

实例 = 压出来的饼干

实例是真正摆在场景里的那一个。同一个 Coin 对象可以摆 3 个实例，它们共享对象设置，但位置、大小、图层可以各自不同。

例：三枚金币分别在三个平台上方。

05 / FIRST GAME

第一个游戏：三枚金币的平台关

这一节是整份指南的主干。你会在一个 1280×720 的空项目里，做出“移动、跳跃、吃金币、加分、掉下去重来、碰旗子过关”的完整循环，最后发布到 gd.games。照着做，不要跳步。

做完你会得到

  • 一个能左右跑、跳的平台角色
  • 3 个平台、3 枚金币、1 面终点旗
  • 金币计数 UI、吃到金币的音效
  • 掉出画面自动重开、碰旗子进入胜利场景
  • 一个可以发给朋友的 gd.games 链接

第 1 步：把场景改名，确认保存

双击顶部的“未命名场景”标签

改成 Level1，回车。然后打开左上角项目管理器，确认 Scenes 列表里有它，并且它被设为启动场景（通常第一个场景会自动成为启动场景）。

为什么先改名：后面事件里“切换场景”要选名字，早点改省得混。

第 2 步：创建玩家对象

右侧对象面板 → 添加对象 → Sprite

路径：对象 → 添加对象 → 从零开始新建对象 → Sprite。对象名填 Player。

在 Sprite 编辑器里点“添加动画”，再点“添加精灵”，选择刚下载的 player.png。一张静态图也能做游戏；动画可以以后再加。点“应用”。

把 Player 从对象面板拖到画布左侧，放在地面高度附近（先随便放，下一步会调）。

第 3 步：给玩家加“平台角色”行为

选中 Player 对象 → 左侧“行为” → 添加行为

搜索 Platformer character（平台角色 / 平台跳跃角色），添加。它自带方向键移动和跳跃，不需要你写移动事件。

先填一组能用的起始值（不同版本的中文标签可能略有差异，认英文即可）：

参数起始值作用
Max speed / 最大速度250跑多快
Acceleration / 加速度1500起步多快
Deceleration / 减速度1800松手后停得多快
Jump speed / 跳跃速度700起跳瞬间的向上速度
Gravity / 重力1500下落加速
Max. falling speed / 最大下落速度1000防止越掉越快
Default controls / 默认控制开启方向键 + 空格/Shift

这组值只是起点。第 11 步会讲怎么根据手感微调。不要一次改五个参数，一次只改一个。

第 4 步：做地面和平台

新建 Sprite 对象 Ground，加 Platform 行为

对象面板 → 添加对象 → Sprite → 命名 Ground → 添加 ground.png。然后选中 Ground 对象，左侧“行为” → 添加行为 → 搜索 Platform（平台），添加，类型保持默认的 Platform。

把 Ground 拖进场景，在左侧属性里设：X = 0，Y = 656，宽 = 1280，高 = 64。这样它正好铺在 720 高的画面底部。

再复制几个平台实例，做成阶梯：

  • 平台 A：X = 320，Y = 520，宽 = 240，高 = 32
  • 平台 B：X = 640，Y = 400，宽 = 240，高 = 32
  • 平台 C：X = 960，Y = 520，宽 = 220，高 = 32

垂直间距约 120–136 px，按上面的跳跃参数是够得着的。水平缺口不要超过 180 px，否则新手容易摔。

第 5 步：让相机跟着玩家

切到“场景（事件）”标签，新建一个空事件

路径：场景（事件） → 添加事件 → 添加动作 → 搜索 camera → 将相机居中到对象 / Center the camera on an object → 选 Player。

这个事件没有条件，所以每帧都会执行，相机就会一直跟着玩家。动作里的图层保持基础层（Base layer）即可。

如果关卡只有一屏宽，相机看不出效果。把地面拉宽到 2400、把平台往右再摆几组，就能看到滚动。你也可以先用“将相机居中到对象并限制范围”，把边界限制在关卡内，避免看到画面外的空白。

第 6 步：金币、碰撞、加分

新建 Coin 对象，摆 3 个实例

对象面板 → 添加对象 → Sprite → 命名 Coin → 添加 coin.png。把它拖到三个平台上方，各放一个。位置不用精确，能跳到就行。

在加事件之前，先在左侧面板展开 “场景变量”，点 + 新建一个数字变量 Score，初始值 0（也可以右键场景 → 场景属性 → 编辑场景变量）。然后新建事件：

Event金币被吃到

Conditions / 条件

C1Player 与 Coin 碰撞（Collision）

Actions / 动作

A1Coin：删除对象（Delete）
A2更改场景变量 Score：+1
A3ScoreText：把文本设为 "金币 " + Score
A4播放声音 coin.wav（可稍后加）

为什么删除的是“碰到的那一枚”，不是全部？因为碰撞条件会把 Coin 的候选实例缩小到“和 Player 接触的那一个”。后面的 Delete 只作用于被选中的实例。这就是 GDevelop 的“对象挑选（object picking）”。第 06 节会详细讲。

如果 ScoreText 还没建好，A3 可以先跳过，第 7 步建好后回来补。金币没消失的话，先检查 Delete 动作的目标是不是 Coin，以及碰撞条件是不是真的加了两个对象。

第 7 步：做分数 UI，并放到 UI 图层

新建 Text 对象 ScoreText

对象面板 → 添加对象 → Text（文本）→ 命名 ScoreText → 内容写 金币 0。字号 32，颜色选一个在背景上看得清的（深色或白色加描边都行）。把它放在画面左上角，比如 X = 24，Y = 20。

打开图层面板（工具栏里的图层按钮），新建一个图层叫 UI。选中 ScoreText 实例，在左侧属性里把它的 Layer 改成 UI。

这样相机跟随只作用于基础层，分数不会跟着世界滚动。背景层也可以这样单独做，但第一个游戏先不用。

如果分数文字跟着场景跑出了画面，八成是它还在基础层。

第 8 步：掉下去就重开

新建事件：Player 的 Y 大于 760 → 切换场景到 Level1

条件：Player → 位置 → Y 位置 → > → 760。动作：场景 → 更改场景 → Level1。

Y 轴向下增加，所以“掉出画面”是 Y 变大，不是变小。760 是画面高度 720 再加一点余量；角色高 48，等它完全掉下去再重开，视觉上更自然。

重开会重置场景变量 Score 和所有金币，所以是“干净的一局”。如果你想让分数跨重开保留，把 Score 改成全局变量（第 08 节）。

第 9 步：终点旗与胜利场景

新建 Flag 对象，放到关卡右侧

用 flag.png 建 Sprite，命名 Flag，放在最后一个平台附近。它不需要 Platform 行为，只是一个碰得到的终点。

新建事件：条件 Player 与 Flag 碰撞；动作 更改场景 → Win。

然后创建 Win 场景：项目管理器 → Scenes → 添加场景；放一个 Text 对象，写“你做到了！”，再写一行小字“按 R 再玩一次”。在 Win 场景的事件里加：按键 R → 更改场景 → Level1。

场景切换会重置场景变量；如果胜利页想显示最终分数，用全局变量 Score，或在切换前把分数写进 Storage。

第 10 步：加音效（可选，但很提气）

在金币事件里加“播放声音”

在 A4 动作里选择“播放声音 / Play a sound”，文件槽里导入一个短的 coin.wav。没有音效就去 Freesound 找 CC0 的短音效，或从免费素材包拿一个。

浏览器限制：网页游戏必须等你先点一下页面/按一次键，才允许播放声音。这是浏览器的自动播放策略，不是 GDevelop 的 bug。正式发布时，最好在第一个场景放一句“点击开始”。

短音效用 WAV；背景音乐用 AAC/M4A，别拿几分钟的 WAV 当 BGM，文件会很大。

第 11 步：预览、试玩、调手感

点“预览”，用方向键和空格试玩

预览会打开一个新窗口。默认从你当前编辑的场景开始。试这几件事：能不能跑、能不能跳、金币是不是只消失一个、分数有没有变、掉下去是不是重开、碰旗子是不是进 Win。

改完参数后，不要关预览——点顶部的“更新 / Update”，它会把改动热更新到正在运行的预览里。这就是“Live Preview”，调手感非常快。

手感调参：一次只改一个
症状先调什么方向
跳得太低，上不去平台Jump speed每次 +50，直到够得着；或把平台降低

第 12 步：发布到 gd.games

点“分享” → gd.games → 发布游戏

确认已登录。顶部“分享”会打开导出面板：gd.games、浏览器、桌面、安卓、iOS、查看所有导出。选 gd.games，点“发布游戏 / Publish game”。

在游戏 dashboard 里可以改 16:9 缩略图、名称、描述、可见性，也可以下架游戏。缩略图很重要，别用默认灰图。

06 / EVENTS

事件系统：GDevelop 的“因果表”

事件表看起来像一张表格，实际上是一条条规则：当这些条件成立，就执行这些动作。理解“每帧执行、从上到下、对象挑选”这三件事，你就跨过了新手最大的坎。

条件（Conditions）

“什么时候做”“对谁做”。例如：玩家碰到金币、分数大于 3、按下了空格、场景刚开始。

条件还负责挑选对象：只有满足条件的实例，才会被后面的动作影响。

动作（Actions）

“做什么”。例如：删除金币、分数 +1、切换场景、播放声音、改变文字。

一个事件可以没有条件（每帧都执行），但不能没有动作（否则什么也不会发生）。

一张事件表长什么样
Event 1金币被吃到

Conditions

C1Player 与 Coin 碰撞

Actions

A1Coin：删除
A2Score：+1
A3ScoreText：设为 "金币 " + Score
规则一：没有条件的事件，每帧都会执行

游戏通常以每秒 60 帧运行。一个没有条件的事件，动作会被执行约 60 次/秒。这既可以是好事（相机每帧跟随），也可以是灾难（每帧给分数 +1，一秒加 60 分）。

最常见的 bug：“碰到金币加分”忘了删除金币，也没加“仅触发一次”。只要玩家还压在金币上，分数就会每帧上涨。解决办法不是加 TimeDelta()，而是让这件事只发生一次：删掉金币，或加“Trigger once while true / 仅触发一次”。
规则二：从上到下执行，顺序会影响结果

事件按列表顺序执行。上面的事件先改变量、先删对象，下面的事件看到的就是改过之后的状态。如果你发现“明明写了却没生效”，先看它上面是不是有事件已经把对象删了、把场景切了、把变量改了。

子事件：子事件只有在父事件的条件成立、并且父事件的动作执行完之后才会运行。适合表达“在……的基础上，再……”。例如父事件“分数 ≥ 3”，子事件“显示胜利文字”。
规则三：对象挑选（Object Picking）

这是 GDevelop 最容易被误会、也最值得花十分钟搞懂的机制。事件里写 Coin，到底是指“所有金币”，还是“某一个金币”？答案是：看它前面被什么条件挑选过。

规则含义例子
第一次使用默认选中场景里该对象的全部实例事件第一行写 Delete Coin，会删掉所有金币
条件会过滤条件只保留满足它的实例，后面的动作只影响这些实例Player 与 Coin 碰撞 → 只选中碰到的那一枚
作用域有限挑选结果只影响当前事件及其子事件；事件结束后恢复这个事件删了一枚金币，不会影响下一个事件里的“所有金币”
特殊动作“Pick all instances”会恢复全部；“Pick a random instance”会随机选一个想做“随机掉落”，先用它选一个

官方文档专门有一页讲 object picking；如果你只记住一句话：条件不只是判断，它还在选对象。

自检方法：在动作的目标对象上问自己——“这个 Coin 是被哪个条件选中的？”如果前面没有任何条件提到 Coin，那它默认就是全部。想只影响一个，就先写碰撞/距离/被点击等条件。
TimeDelta()：让速度不随帧率变化

有些操作是“持续”的：旋转、移动、冷却、逐渐加速。这类操作要用 TimeDelta() 乘一下。它返回上一帧到这一帧经过的秒数。这样在 30 帧和 60 帧的电脑上，速度看起来一致。

// 让物体每秒旋转 90 度，而不是每帧旋转 90 度 每帧：Rotate 对象 → 角度增加 90 * TimeDelta() // 让变量按“每秒 100”的速度增长，而不是“每帧 100” 每帧：Change variable Score → + 100 * TimeDelta()

计分、一次性开关、碰撞删除这类“瞬间发生”的动作，不需要乘 TimeDelta。只有“持续一段时间”的变化才需要。

Trigger once：只想让它发生一次

条件面板里搜 Trigger once while true（仅触发一次）。它适合“分数达到 3 时显示提示”“玩家第一次进入区域时弹对话”这类只需要触发一次的规则。它不适合“碰到金币就删除”——那种情况直接删金币更自然。

07 / OBJECTS & ASSETS

对象、图层与素材：画面是怎么被组织起来的

GDevelop 里“看到的东西”几乎都是对象。对象负责长相和能力，实例负责摆在哪里，图层负责前后关系和相机，素材负责长相的来源。把这三层分开想，画面就不会乱。

Sprite 的五个关键设置

动画（Animation）

一个 Sprite 可以有多组动画：Idle、Run、Jump、Hurt。每组可以有多帧，设置每帧间隔（默认 0.08 秒）和是否循环。

给动画起名字（Idle/Run），事件里用名字切换，比记编号可靠。

碰撞掩码（Collision Mask）

决定“哪里算碰到”。默认可能是整张图（包括透明边），会让角色看起来悬空或卡住。用“编辑碰撞掩码”裁到身体/脚底。

平台角色使用自定义掩码时，实际只用掩码外围的矩形做平台碰撞；别把掩码画得太碎。

原点与点（Origin / Points）

原点决定对象位置对应图片的哪个位置；点可以标记枪口、脚底、头顶，用于生成子弹或对齐。

第一个游戏保持默认即可，遇到“角色位置怪怪的”再检查。

图层与 Z 顺序

图层决定大块的前后关系（背景/游戏/UI）；同一图层内用 Z-order 决定谁盖住谁。

UI 永远单独一层；背景可以单独一层并降低视差速度。

翻转、染色、混合模式

Flip 可以左右翻转角色，省一套图；Change color 可以受伤闪红；混合模式可以做发光/阴影。

这些都是事件动作，不用改原图。

可见性

实例可以在属性里设为“开始时隐藏”，之后用事件显示。适合胜利文字、对话、还没解锁的按钮。

隐藏不等于删除：它仍然存在，仍然参与碰撞和事件。

图层与相机：为什么 UI 会跟着跑

每个图层都有自己的相机。默认所有对象在 Base layer，相机跟随玩家时，整层一起动。把分数放到新建的 UI 层，UI 层的相机不动，文字就固定在屏幕上。

图层放什么相机
Background天空、远山、背景装饰可以比游戏层移动得慢，做视差
Base layer玩家、平台、金币、敌人跟随玩家 / 限制在关卡边界内
UI分数、血量、按钮、对话固定不动

图层还可以整体隐藏、改时间缩放、加视觉效果。效果很酷但吃性能，先别给每一层都加。

素材从哪来：免费不等于随便用

GDevelop 素材商店

编辑器内直接浏览，免费包和付费包都有。每个包会写授权；下载前看清楚能不能商用、要不要署名。

Kenney

大量 CC0 游戏素材，适合原型。仍然建议保留来源记录，别把“免费”当成“无主”。

OpenGameArt / itch.io

质量参差，授权混杂。每个包单独看 License：CC0、CC-BY、CC-BY-SA 的义务不同。

不要直接从 Google 图片、Pinterest、动漫截图里抠图。“我没收钱”不是授权。商用、公开发布、甚至放到 gd.games 都可能涉及版权。用 CC0/CC-BY 素材，或自己画/买授权，并保留 license 文本。
素材类型推荐格式注意
角色/道具/平台PNG（透明背景）像素风关闭平滑/用最近邻；别用超大图再缩小
背景PNG / JPG控制尺寸；4K 背景会拖慢加载

整理项目的三个小习惯
  • 命名统一：Player、Coin、ScoreText，不要用“新建对象1”“精灵2”。事件里全是一堆“新建对象”，你会疯。
  • 一个场景一件事：Level1、Level2、Win、Menu 分开；不要把所有关卡塞进一个场景。
  • 对象组：把 Coin、Gem、Heart 放进 Collectibles 组，事件里可以对组统一处理。等对象多了再学，不要一开始就过度设计。
关于 3D：GDevelop 支持 3D 对象、3D 相机和一些 3D 逻辑，但它的强项仍是 2D。第三方评测普遍认为 3D 功能在成熟中；如果你是第一次做游戏，先用 2D 把“完成一个游戏”的流程走通。
08 / VARIABLES & SAVE

变量与存档：让游戏记住“刚刚发生了什么”

分数、血量、是否拿到钥匙、最高纪录——这些都是变量。变量只在游戏运行期间存在；想让玩家关掉游戏后还记得，就要用 Storage 写进本地存储。

四个作用域，先分清“活多久”
作用域在哪建活多久典型用途
全局变量 Global项目/游戏设置里的全局变量整个游戏运行期间；切场景不丢；关游戏就丢总分、已解锁关卡、玩家名字
场景变量 Scene左侧面板 → 场景变量（或场景右键 → 场景属性）只在当前场景；切场景/重开就重置本关金币数、本关计时
对象变量 Object对象编辑器里的变量跟着对象走；事件里用 对象名.变量名敌人的血量、NPC 的状态
事件局部 Local事件里的局部变量只在这个事件/子事件内临时计算、循环计数
数据类型与写法

五种类型

  • Number：0、100、-10、3.5
  • Text："你好"、玩家名
  • Boolean：真/假
  • Structure：带字段的集合，如 player.name
  • Array：列表，如背包物品

表达式里怎么用

// 场景/全局变量 Score // 对象变量 Player.Health // 拼文字 "金币 " + Score

变量名不要含空格、点、逗号；用 camelCase 或下划线。

场景变量还是全局变量？问自己：“切到下一关，这个值还要不要？”要，就用全局；不要，就用场景。第一个游戏的金币分数用场景变量最简单，掉下去重开就归零，符合“干净的一局”。
Storage：真正把进度写下来

GDevelop 的 Storage 动作会把数据写进运行环境的内部存储：网页游戏用浏览器的 LocalStorage，桌面游戏用应用自己的本地存储。它适合存最高分、已解锁关卡、设置项。

概念怎么理解例子
Storage像“文件名”，一个存储空间save、settings
Group像“文件夹/分区”，可用斜杠分层progress/bestScore、progress/level
Value实际存的值，只支持数字和字符串1200、"Level2"

布尔值不是原生存储类型：存成 1/0 或 "true"/"false"。Storage 不跟着账号走，换设备/换浏览器不会自动同步。

一个最小存档流程
Level1 结束时写入最高分与进度

Conditions

C1Player 与 Flag 碰撞

Actions

A1Storage save / group progress / key bestScore ← Score
A2Storage save / group progress / key level ← 2
A3更改场景 → Win

下次启动时，在菜单/第一场景读取 save 的 progress/bestScore，写进一个全局变量，再显示“最高分”。如果读不到（第一次玩），就保持默认 0。

Storage 不是“云存档”

它存在玩家自己的浏览器/设备里。清浏览器数据、换浏览器、换电脑、无痕模式，都可能让存档消失。云项目保存的是“你的项目”，不是“玩家的进度”。

测试时怎么清存档

预览窗口里打开开发者工具（View → Toggle developer tools），到 Application → Local Storage，找到对应条目清除。官方文档也给了这个流程。

清完重开预览，就是“第一次玩”的状态。

存档的安全边界
  • LocalStorage 可以被玩家手动修改，不要把“付费解锁”“排行榜分数”只信本地值。
  • 不要把密码、身份证、真实地址等敏感信息写进 Storage 或游戏文件。
  • 做排行榜/联机时，分数要服务器校验；GDevelop 的在线服务能帮一部分，但不是自动防作弊。
  • 发布前测试“第一次玩”和“有存档”两条路径，别只测其中一条。
调试变量：用“预览”下拉菜单里的调试器，可以暂停游戏、查看全局/场景/对象变量的实时值。比在事件里到处加文字打印快得多。第 11 节会讲怎么打开。
09 / BEHAVIORS

行为（Behaviors）：少写事件，先让东西动起来

行为是别人（官方或社区）写好的“能力包”：平台跳跃、俯视移动、物理、寻路、拖拽。加到对象上，再调几个参数，就能省掉大量事件。新手最容易犯的错，是一次加太多行为，然后不知道谁在改位置。

常用行为速查
行为给它什么对象能做什么注意
Platformer character玩家、敌人左右跑、跳、下跳、爬梯、抓边默认方向键 + 空格/Shift；可在参数里关掉默认控制
Platform地面、平台、墙让角色站上去/撞上去类型有 Platform、Jumpthru、Ladder；平台和角色都要开抓边才能抓
Top-down movement俯视角角色4/8 方向移动，可调加速度、朝向适合 RPG、俯视射击；图片朝向不对就调 Angle offset
Physics2球、箱子、碎片重力、弹力、摩擦、碰撞真实但不精确，做平台跳跃会很滑；调参成本高
Pathfinding敌人、NPC绕开障碍走到目标点需要障碍物/可行走区域设置；场景大时注意性能
TweenUI、道具、相机在指定时间内平滑改变位置/大小/角度/透明度做弹出菜单、飘字、过场很好用
Draggable拼图块、卡片鼠标/触摸拖动要处理“放回原位”“吸附”等逻辑
Destroy outside screen子弹、掉落物离开画面自动删除防止对象越积越多拖慢游戏
平台角色的参数，到底在调什么

移动手感

  • Max speed：最高跑速
  • Acceleration：从静止到最高速有多快
  • Deceleration：松手后停得多快
  • Slope max angle：能爬多陡的坡；0 度只能走平地

跳跃手感

  • Jump speed：起跳初速度，决定跳多高
  • Gravity：下落加速度，决定“飘不飘”
  • Jump sustain time：按住跳键能维持初速度多久
  • Max falling speed：最大下落速度，防止越掉越快
先调 Jump speed，再调 Gravity。跳不上去 → 加 Jump speed；跳得飘 → 加 Gravity。两个一起大改，你会不知道是哪个起了作用。热更新开着，边玩边调。
平台、跳穿平台、梯子
Platform 类型效果适合
Platform实心：能站、能撞墙地面、墙、实心平台
Jumpthru从下面能跳穿，从上面能站；按下键可下落浮空平台、单向平台
Ladder可上下爬，不碰撞阻挡梯子、藤蔓
俯视移动：RPG 和射击的起点

给角色加 Top-down movement，可以选择 4 方向或 8 方向，调加速度、减速度、最大速度和转向速度。默认角色角度 0 朝右；如果你的图片朝上，改 Angle offset，不然移动时角色会“横着走”。

扩展与自定义行为

行为列表里有很多官方扩展，也有社区扩展。官方审核过的扩展更稳；社区扩展可能缺文档、停更或和当前版本不兼容。装之前先看说明、评分和最近更新时间。

  • 先装一个，测试一个。不要一次装五个，否则出问题不知道是谁。
  • 读行为参数。很多“bug”其实是参数默认值不适合你的游戏。
  • AI 的边界：GDevelop AI 了解内置功能和官方审核过的扩展；社区扩展它可能不知道，别指望它替你调试。
  • 自定义行为：熟练后可以把重复逻辑封装成行为，给自己或团队复用。
行为冲突：同一个对象上，Platformer character 和 Physics2 都在改位置，通常不会得到“更真实”的效果，而是互相打架。一个角色只选一套主移动方案。要加“被击退”“弹簧”等效果，用事件临时改变速度，而不是再叠一个物理行为。
10 / AI ASSISTANT

AI 助手：把它当助教，不要当代做

GDevelop 内置的 Ask AI 不只是聊天机器人：它能读你的对象、行为、变量和事件，也能直接改项目。用得好，它能把“我不知道从哪下手”变成“我知道下一步试什么”；用不好，它会在你的项目里留下一堆你不理解的逻辑。

它擅长

  • 解释某个行为/条件/动作是干什么的
  • 按你的描述搭一小段机制（二段跳、追逐敌人、血条）
  • 检查你写的事件，指出对象挑选/变量作用域问题
  • 把“我想要……”翻译成 GDevelop 的具体步骤
  • 给美术/关卡/命名提建议

它不擅长

  • 一次生成完整、好玩、无 bug 的商业游戏
  • 理解你没说清楚的“感觉”和“氛围”
  • 保证代码/事件一定正确；它会自信地犯错
  • 知道未审核的社区扩展
  • 代替你测试、判断“好不好玩”
怎么打开、怎么控制它

点右上角“Ask AI”

在编辑器里打开对话面板。它会读取当前项目结构；你描述需求，它决定是回答、解释，还是直接动手改。

先关掉 Auto edit，把需求聊清楚

Auto edit 开：AI 直接改项目，适合“我已经想清楚，你给我搭”。Auto edit 关：它只能读和建议，每次改动都问你，适合规划、学习、怕它乱改。

推荐流程：先关掉 Auto edit 聊方案 → 确认后打开 Auto edit 让它做 → 做完立刻试玩验收。

选推理等级

Medium 所有人可用，日常够用；High 需要 Gold/Pro，适合复杂机制；Maximum 需要 Pro，适合最难的请求。等级越高，思考越久、消耗越多。

不要什么都用最高档。一个“金币怎么旋转”的问题，Medium 足够。

盯着它的步骤，随时 Stop

复杂请求会拆成多步：探索项目、检查结构、编辑游戏、搜索素材。每一步都能展开看它做了什么。发现方向不对，点 Stop，重新描述，不要等它跑完再后悔。

重要：对云项目，GDevelop 会在你每次发消息/请求前自动保存一个恢复点，可以回滚。对本地项目，这个自动恢复点没有——在用 AI 大改之前，自己先另存一份。恢复会覆盖当前状态，确认后再点。
好用的提示词，长什么样

公式：目标 + 现状 + 具体数值 + 不要改什么 + 验收标准。不要只说“帮我做个游戏”，那等于让设计师猜。

示例 1：加机制

“我的 Player 已经有 Platformer character 行为。请加二段跳：在空中再按一次空格可以再跳一次，落地后重置。不要改移动速度、重力和碰撞掩码。做完告诉我改了哪些事件，并说明怎么测试。”

示例 2：修 bug

“金币吃到后分数不增加。现有事件是 Player 与 Coin 碰撞 → 删除 Coin → 场景变量 Score +1 → ScoreText 设为 "金币 " + Score。请先解释可能是对象挑选、变量作用域还是文本目标的问题，再检查并修复，不要重写整个项目。”

示例 3：做敌人

“做一个巡逻敌人：在平台上左右走，看到玩家靠近 200 px 就追，碰到玩家让玩家回到起点。用现有对象，不要新增付费素材。先给方案，我确认后再改。”

AI 的隐私与边界
  • 官方说明：AI 不会用你的项目训练模型；本地/云项目只在对话期间对它可见；它不能浏览互联网。
  • 它看不到你的用户名、排行榜、分析数据等个人信息。
  • 它可能误解你的游戏，或把社区扩展当成不存在。关键改动一定自己试玩。
  • 不要让 AI 替你决定付费、公开发布或填写个人信息。
  • 把好用的提示词记下来，下次直接复用，比每次重新描述省额度。
AI 能帮你更快地到达“可以玩”，但不能替你判断“好不好玩”。后者只能靠你一遍遍试。—— 让 AI 做脚手架，你做判断
11 / PREVIEW & DEBUG

预览、调试、排错：把“为什么不动”变成“我知道哪里错”

做游戏的时间，大概一半花在“它怎么不按我想的动”。这一节给你一套可重复的排查顺序，以及在线编辑器里最常用的预览/调试工具。

预览的四种用法
操作怎么用适合
预览 / Preview点顶部“预览”，从当前场景启动每次改完一小段，快速试玩
更新 / Update预览开着时，预览按钮会变成“更新”，把改动热更新进去调手感、改数值、改 UI，不想从头玩
多开预览预览按钮旁的下拉菜单里再开一个窗口对比两个版本、测试联机
网络预览 / Network preview下拉菜单选 Network preview，用同一 Wi-Fi 的手机浏览器打开地址测试手机触控、横屏、真实设备性能

也可以在下拉菜单里指定“用这个场景启动所有预览”，避免每次都从第一关开始。这个设置会保存在项目里。

调试器与性能分析器

打开预览下拉菜单 → “使用调试器和性能分析器预览”

会同时打开游戏预览和一个 Debugger 标签。你可以暂停游戏，查看全局变量、场景变量、对象/实例的实时值。

先看变量，再看实例

分数不对？先看 Score 的实际值。金币没删？看 Coin 的实例数量。角色位置怪？看 Player 的 X/Y 和当前动画。

卡顿就看 Profiler

性能分析器会显示时间花在事件还是渲染上。如果事件很轻但帧率低，可能是对象/粒子/特效/大图太多；如果事件很重，检查有没有每帧遍历大量对象。

浏览器开发者工具也能帮忙：在预览窗口按 F12（或右键 → 检查）打开 Console，能看到 JavaScript 报错和资源加载失败。它不是 GDevelop 的官方调试器，但排“黑屏/资源 404”很快。
一套不会乱的排错顺序

1. 复现

用最短步骤重现：哪个场景、按了什么、期望什么、实际什么。能稳定复现，才容易修。

2. 隔离

关掉其他事件/行为/效果，只留最相关的一条。问题消失，说明被关掉的东西里有元凶。

3. 看数据

用调试器看变量、实例数、位置。不要靠猜“应该是对的”。

4. 查对象

对象有没有行为？碰撞掩码？图层？Z 顺序？实例是不是选错了？

5. 查顺序

上面的事件是不是已经删了对象/切了场景/改了变量？

6. 最小化

新建一个空场景，只放两个对象和一条事件，能复现就说明逻辑本身有问题；不能就是环境/其他对象干扰。

常见问题速查

在下面输入关键词过滤，比如“金币”“声音”“存档”“黑屏”。

共 12 条，显示全部

编辑器一直加载 / 白屏 / 卡在启动画面

先排除环境：换 Chrome/Edge 无痕窗口打开；关掉广告拦截/脚本拦截插件；换网络；确认不是公司/学校网络拦截了 WebSocket。

再看控制台：F12 打开 Console，如果有红色报错/资源 404，截图留着。第一次加载本来就慢，给它 30–60 秒，不要连续刷新。

如果只有你的账号这样：退出重登，或换一个浏览器登录，判断是账号/缓存还是设备问题。
云项目保存失败 / 一直显示保存中

最常见是网络波动、登录状态过期、或同一项目在多处同时编辑。先别关页面，复制一份关键内容/截图，再检查网络和登录状态。

如果提示冲突，选一个版本继续，不要把两个版本来回覆盖。长期项目建议用桌面版本地保存作为主副本。

养成习惯：大改之前先确认“已保存”；重要版本用“另存为”留一个副本。
预览是黑屏 / 空窗口

检查：当前场景是不是空的？相机是不是被移到了别处？对象是不是在隐藏图层/被设为隐藏？场景的启动场景是不是选错了？

先放一个 Text 对象在 (0,0)，如果文字能看到，说明渲染正常，问题在对象/相机/图层；如果文字也看不到，检查预览窗口和浏览器控制台。

临时把相机动作关掉，再预览一次。相机跑飞是“黑屏”的常见原因。
角色不掉落 / 直接穿过地面

地面对象有没有 Platform 行为？角色有没有 Platformer character？地面实例的碰撞掩码是不是太小/被裁掉了？角色速度是不是大到一帧穿过薄平台？

平台类型也要对：Jumpthru 从下面可以穿，Ladder 不碰撞。地面用默认 Platform。

把角色起始位置抬高 50 px，地面加厚到 64 px，再试。仍穿就检查掩码。
按方向键/空格没反应，跳不起来

先点一下预览窗口，让它获得键盘焦点。然后检查 Platformer character 的 Default controls 是否开启；如果关了，你必须自己用键盘事件写移动。

也有可能是输入法/浏览器快捷键拦截了空格。换一个浏览器或换按键测试。

在事件里临时加“按键按下 → 显示文字”，确认按键事件本身有没有触发。
一碰金币，所有金币都消失 / 金币不消失

全消失：Delete 动作所在的事件里，Coin 没有被碰撞条件“挑选”过，默认选中了全部。把碰撞条件放在同一个事件里，且条件里包含 Coin。

不消失：Delete 的目标选错对象；碰撞条件没有真正加两个对象；或者金币在另一个图层/被遮挡，角色其实没碰到。

用调试器看 Coin 的实例数：碰撞前是 3，碰撞后应该变成 2，而不是 0。
分数不增加 / 文字不更新 / 文字叠在一起

分数不增加：检查变量作用域（场景/全局）、动作目标、事件是否真的执行。文字不更新：确认动作目标是场景里的 ScoreText 实例，而不是对象默认文本；表达式里变量名拼写一致。

文字叠在一起：可能创建了多个 Text 实例，或每帧创建一个新的。只保留一个实例，用“修改文本”而不是“创建对象”。

在调试器里看 Score 的值；如果 Score 变了但文字没变，问题在文本动作，不在计分。
切换场景后分数/进度归零

场景变量只活在当前场景，切场景会重置。需要跨场景保留的值，改用全局变量；需要关游戏后还保留的，用 Storage。

注意：重开当前场景也会重置场景变量。如果你的“掉下去重开”是用“更改场景到 Level1”，分数归零是预期行为。

先决定“这个值该活多久”，再选变量作用域，不要全用全局。
声音不播放 / 只有第一次有声音

浏览器要求用户先交互（点击/按键）才允许音频。预览时先点一下画面再试。检查系统/标签页是否静音，文件格式是否被浏览器支持。

短音效用 WAV，音乐用 AAC/M4A。文件太大或采样率奇怪也可能失败。别用“播放音乐”的动作去播很短的点击音效。

换一个确定能播的短 WAV 测试；能播就是原文件问题，不能播就是交互/格式/路径问题。
发布/构建失败，或按钮点了没反应

确认已登录、网络稳定、没有触发当日打包次数上限。桌面/Android 一键打包要填合法的包名（如 com.yourname.gamename）、版本号（如 1.0.0）和图标。

构建是排队任务，慢不等于失败。看界面上的错误提示，不要连续点十次。

先用 gd.games 发布（免费、不限量）验证游戏本身；再做桌面/移动打包。
手机网络预览打不开

手机和电脑必须连同一个 Wi-Fi；电脑防火墙可能拦截了端口；有些公共 Wi-Fi/校园网开启了设备隔离，设备之间不能互访。

用手机流量/另一个网络通常不行，因为预览地址是局域网地址。

换一个手机热点让电脑和手机都连它，再试网络预览；或者直接发布到 gd.games 用链接测试。
越做越卡 / 风扇狂转 / 预览掉帧

常见原因：粒子/特效太多、超大背景图、每帧创建对象不删除、大量对象同时播放动画、调试器/多个预览窗口同时开。

先关掉所有效果和粒子，看是否恢复；再逐个开。用 Profiler 看时间花在事件还是渲染。

给子弹/掉落物加“离开屏幕删除”；把不用的对象设为不播放动画；缩小图片尺寸。
修 bug 的心态：一次只改一个变量，一次只验证一个假设。不要“把能想到的都改一遍”，那样即使好了，你也不知道为什么好，下次还会犯。
12 / PUBLISH

发布与导出：把“我做的”变成“你能玩”

发布不是最后一步的魔法按钮，而是一条分流：想快速给朋友玩，走 gd.games；想上架 itch.io，导出 Web；想做 Windows 应用，走桌面打包；想上手机商店，走 Android/iOS。不同路线的时间、费用和门槛不一样。

路线 A：gd.games（推荐第一次发布）

登录 → 分享 → gd.games → 发布游戏

构建完成后会显示链接和二维码。任何人拿到链接都能在浏览器里玩，不需要装东西。官方说明托管免费，链接会保留。

填好游戏页：名称、描述、16:9 缩略图

在游戏 dashboard 里点“Edit details”。缩略图直接影响点击率，别用默认图。描述里写清楚操作方式（方向键/空格/点击）。

用“Update game page”开关控制公开/测试

发布新版本时，开关开：所有人看到新版本；关：公开页保持旧版，你拿到一个独立的测试链接。给朋友挑 bug 时用后者。

看反馈、更新、必要时下架

dashboard 里有链接、分析、玩家反馈、排行榜/多人服务等。下架在 Edit details 里关掉 “Publish game on gd.games”；构建和分析会保留，公开页消失。

路线 B：Web 导出，上传到 itch.io 等

步骤

  1. 分享 → 浏览器 → 导出。
  2. 得到一个文件夹，里面有 index.html 和资源。
  3. 把整个文件夹压缩成 zip（itch.io 要 zip）。
  4. 在 itch.io 新建项目，类型选 HTML，上传 zip，勾选“This file will be played in the browser”。
  5. 设置封面、截图、操作说明，发布。

注意

  • 不要只上传 index.html，资源要一起。
  • 本地双击打开可能因浏览器安全策略失败；用本地服务器或直接上传测试。
  • Poki/CrazyGames 等平台有自己的 SDK、审核和分成规则，先读它们的开发者文档。
  • 游戏里不要引用你电脑上的绝对路径。
路线 C：桌面打包（Windows / macOS / Linux）
检查项要求
包名像 com.yourname.gamename；只能用字母、数字、点；点之间要有词；2–5 段；不能和已有应用冲突
版本号像 1.0.0、1.0.1
图标按界面要求提供不同尺寸
签名未签名包在 Windows 会触发 SmartScreen，在 macOS 会提示“无法验证开发者”；正式分发需要自己处理签名/公证
构建次数免费 1 次/天；Silver 10 次/天；Gold 100 次/天；Pro 不限
路线 D：Android

APK vs AAB

APK：直接发给手机安装，适合自己测试。Android 会提示“允许来自此来源的应用”。

AAB：Google Play 要求的格式，不能直接安装，要上传到 Play Console。

免费档 1 次/天；Silver 10 次/天；Gold 100 次/天；Pro 不限。

上架 Google Play 的额外成本

需要 Google Play 开发者账号（注册费以 Google 官方为准），还要准备商店图标、截图、隐私政策、内容分级。GDevelop 只负责生成包，不替你过审。

路线 E：iOS（Gold 起）
不是“点一下就能上架”。iOS 需要 Apple Developer Program（年费，以 Apple 官网为准）、证书、Provisioning Profile、App Store Connect 配置，还要过 App Store 审核。GDevelop 的 Gold 档提供 15 次/月 iOS 打包，Pro 30 次/月；免费和 Silver 不含 iOS 发布。

如果你是第一次做游戏，不要从 iOS 开始。先用 gd.games 或 Web 把游戏做完、验证好玩，再考虑移动商店。

发布前检查清单

游戏本身

  • 标题、缩略图、描述、操作说明都填了
  • 手机横屏/竖屏下 UI 不被裁切
  • 第一次点击后声音正常
  • 没有测试文字、占位图、个人信息
  • 素材授权允许公开发布/商用
  • 能从开始玩到结束，不死循环

技术与流程

  • 包名/版本/图标符合要求（桌面/移动）
  • 知道自己还剩几次打包额度
  • 发布了测试版，找一个人独立试玩
  • 记录了这个版本的备份/恢复点
  • 想好发布后去哪收反馈
发布不是终点

第一次发布的目标不是“爆火”，而是完成一次真实的反馈循环：有人玩 → 有人卡住 → 你改 → 再发布。哪怕只有三个朋友玩，他们卡住的地方也比你自己猜的准。

一个发布出去的粗糙小游戏，比一个永远在电脑里的完美企划更有价值。—— 先把循环跑通

14 / LIMITS

边界与局限：什么时候它够用，什么时候该换

一份只讲优点的指南是不负责的。GDevelop 在线版能带你走很远，但它有明确的天花板。提前知道，能避免“做到一半才发现工具不合适”的挫败。

1. 浏览器不是无限性能

在线编辑器跑在浏览器里，受内存、WebGL、标签页资源限制。超大场景、大量粒子/特效、很多高分辨率素材、同时开多个预览，都可能让帧率下降。

第三方观点 一些评测也提到 GDevelop 在大型项目上的性能上限；这不是官方指标，但和你实际体验相符时，换桌面版或缩小规模是合理的。

2. 云依赖与 3 个项目

在线版没有网络就很难工作；免费账号只有 3 个云项目。网络不稳、账号冲突、云服务维护，都可能打断你。

对策：认真做时用桌面版本地保存；云项目只放当前活跃的；重要版本另存备份。

3. 本地文件与离线

在线编辑器可以手动下载项目 zip 作备份，但不能像桌面软件那样持续保存/覆盖本地文件夹，也不适合 Git、离线编辑。需要这些，就用桌面版。

这不是“功能阉割”，是浏览器安全模型的限制；官方也把持续的本地编辑导向桌面应用。

4. 3D 仍在成熟中

GDevelop 能做 3D 对象、3D 相机和一些 3D 游戏，但生态、教程、工作流更偏 2D。复杂 3D 项目通常会用 Unity/Unreal/Godot。

第三方观点 多家评测认为它的 3D 功能在发展中；不要拿它和做了十几年 3D 的引擎硬比。

5. 没有主机一键导出

官方发布路线是 Web、桌面、Android、iOS。Switch / PlayStation / Xbox 不在官方一键导出范围；主机开发需要平台方授权和专门的移植工作。

6. 打包次数与商店成本

免费档桌面/Android 每天各 1 次；iOS 需要 Gold 起，还要 Apple Developer 年费；Google Play 也要开发者账号。发布不是完全零成本。

7. AI 会犯错

它可能误解需求、用错对象、写出你不理解的逻辑，甚至“自信地修坏”。云项目有恢复点，本地项目要自己备份。

8. 工具不保证有人玩

做完、发布、被看见、被喜欢，是四件不同的事。GDevelop 解决“能做出来”；发行、社区、运气、持续更新，它不包。
